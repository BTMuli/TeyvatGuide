# 界面信息与辅助文案规则

适用于页面、组件与浮层的信息组织和用户可见文案。

**避免不必要的辅助标签与说明，让布局本身发挥解释作用。**

## 先用布局表达关系

- 用分组、留白、对齐、字号层级和稳定的操作位置表达内容归属、主次与操作关系。
- 界面难以理解时，先调整结构、命名与操作位置，不默认追加说明来弥补布局问题。
- 不为填补留白、装饰卡片或重复标题而增加眉题、徽标、副标题；能从当前上下文直接理解的操作，不再配
  「点击下方按钮……」等提示。

## 辅助文案按需出现

- 仅在文案能消除真实歧义，或补充影响用户选择、操作的信息时保留，例如适用条件、输入约束、操作后果
  和错误恢复方法；避免重复标题、按钮名称或已展示的状态。
- 必要说明紧邻相关内容或控件，优先在需要它的状态出现；较长的补充帮助可以按需展开。
- 不把实现细节、内部术语或设计意图写成面向用户的说明，除非它们确实影响用户的判断。

## 保留必要信息与可访问性

- 精简不等于删除必要的字段标签、单位、状态、风险提示与错误信息；不要用 placeholder 代替字段标签，
  也不要把关键约束或操作后果只放在悬停提示中。
- 保留语义化标题、控件的可访问名称和必要的描述关联；布局与颜色不能替代这些语义。图标按钮和复合
  点击区域的键盘与语义要求见[交互元素与点击区域规则](interaction-rules.md)。

## 自检与适用范围

- 逐条检查辅助标签与说明：移除后是否仍能理解内容归属、当前状态与下一步操作？能则删除；不能则先
  检查布局与命名，仍有必要的信息再用简短文案补充，并确认窄屏与键盘使用时同样清楚。
- 新增或当前任务涉及的界面按本规则处理，不因此批量清理任务范围外的既有文案。
