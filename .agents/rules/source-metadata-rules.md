# 源代码版本与注释元数据规则

本规则约束本次任务实际修改的源代码文件，不要求为未修改的历史代码批量补齐或重写元数据。

## 版本来源

- 先读取根目录 `package.json`，所有本次 `@since` 使用其中的 `since` 属性，不使用 `version`。
- 标记格式为 `@since Beta v<package.json.since>`；尖括号中的内容是占位符，实际注释应替换为读取到的版本值。
- 只把当前任务涉及的文件、函数和类型更新到该版本，保留无关声明的历史版本标记。

## 文件头

- 除 `.vue` 外，修改支持注释的源代码文件都要更新文件头 `@since`。范围包括 `.ts`、`.d.ts`、`.js`、`.css`、`.scss`、`.sql`、`.rs` 等仓库源文件。
- 文件原本没有文件头时，补充符合语言语法的文件说明和 `@since`。沿用邻近代码的注释形式：TypeScript/CSS/SCSS 使用块注释，SQL 使用 `--`，Rust 使用模块或普通注释（如 `//!`/`//`）。
- `.vue` 文件不强制新增或更新文件头；文件中已有的函数或类型注释仍须按下述规则随声明修改更新。
- JSON、锁文件、生成物和二进制文件不要为了写入 `@since` 插入非法注释。

## 函数注释

- 函数实现或签名发生修改时，无论是否导出，都更新紧邻函数注释中的 `@since`；已有注释缺少 `@since` 时补齐。
- 除 `.vue` 外，修改的函数没有注释时，补充符合语言规范的简要说明、`@since`，以及必要的参数和返回值说明。
- `.vue` 仅豁免“无注释函数必须补注释”这一要求；若已有函数注释，修改函数时仍须更新其 `@since`。

## 类型注释

- 修改类型声明时（包括新增、删除、重命名字段或改变字段类型），更新类型声明自身的 `@since`。TypeScript 的 `type`、Rust 的结构体等声明的版本标记由声明注释承载，不能用字段注释替代。
- 不因修改一个类型而批量更新无关类型或字段的历史 `@since`；`.vue` 中已有类型注释随声明修改同样更新。

## 复用类型与枚举

类型复用和抽离遵循 [TypeScript 规则](typescript-rules.md)；枚举或运行时常量的复用、抽离遵循 [枚举规则](../skills/typescript-standards/references/enum.md)。
